## Build and test

The commands below are the ones gherkin-ai uses to verify this stack. Run them in `generated-specs` with the toolchain installed, or inside the official image `elixir:1.17`.

```bash
cd generated-specs
mix local.hex --force --if-missing > /dev/null
mix local.rebar --force --if-missing > /dev/null
mix deps.get > /dev/null
mix compile --warnings-as-errors
mix test
```

Runtime integration suite (IT1–IT7: transactional outbox, idempotency under concurrency, exactly-once relay, tenant isolation, saga compensation, inbox deduplication and dead-lettering, trace propagation), plus an HTTP test of the generated API (tenant from the JWT, idempotency key, outbox):

```bash
docker run -d --name ghk-pg -e POSTGRES_PASSWORD=ghk -p 5432:5432 postgres:17-alpine
docker run -d --name ghk-mq -e RABBITMQ_DEFAULT_USER=ghk -e RABBITMQ_DEFAULT_PASS=ghk -p 5672:5672 rabbitmq:4-alpine
export DATABASE_URL=postgres://postgres:ghk@localhost:5432/postgres AMQP_URL=amqp://ghk:ghk@localhost:5672
mix test --only integration
```

The same suite runs against the Google Cloud Pub/Sub emulator. The gherkin-ai golden `phoenix-pubsub` verifies this runtime's Pub/Sub adapter:

```bash
docker run -d --name ghk-pubsub -p 8085:8085 gcr.io/google.com/cloudsdktool/google-cloud-cli:emulators \
  gcloud beta emulators pubsub start --host-port=0.0.0.0:8085 --project=local-project
export GHK_BROKER=pubsub PUBSUB_EMULATOR_HOST=localhost:8085 PUBSUB_PROJECT_ID=local-project
mix test --only integration
```

## Production image and cloud deployment

`generated-specs/` has a production `Dockerfile` (multi-stage, non-root user) and a `.dockerignore`. The image is configured only through environment variables, so the same image runs on AWS ECS Fargate, Google Cloud Run, Azure Container Apps or Kubernetes. It listens on port 4000, with one health probe, `/health`, for liveness and readiness.

```bash
cd generated-specs
docker build -t transactional-system-elixir-phoenix .
docker run --rm -p 4000:4000 \
  -e DATABASE_URL=postgres://postgres:ghk@host.docker.internal:5432/postgres \
  -e AMQP_URL=amqp://ghk:ghk@host.docker.internal:5672 \
  -e JWT_SECRET='change-me-to-a-secret-of-32-chars!' \
  -e SECRET_KEY_BASE="$SECRET_KEY_BASE" \
  transactional-system-elixir-phoenix
curl -f http://localhost:4000/health
```

Set `SECRET_KEY_BASE` in your shell first; in a real deployment it comes from the platform's secret manager.

The runtime kernel chooses its event broker when it starts: `GHK_BROKER` if set, otherwise the broker whose variables are present, otherwise `stack.messaging`.

| Cloud | Broker | Variables |
|---|---|---|
| AWS | Amazon MQ for RabbitMQ | `AMQP_URL` (the broker's `amqps://` endpoint) |
| GCP | Pub/Sub | `GHK_BROKER=pubsub`, `PUBSUB_PROJECT_ID`; the token comes from the workload identity |
| Azure | Self-managed RabbitMQ or CloudAMQP | `AMQP_URL` (there is no official Service Bus SDK for this language) |

The full list of variables and the per-cloud services are in the [deployment guide](https://github.com/FennerEduardo/gherkin-ai-cli/blob/main/docs/DEPLOYMENT.md).
